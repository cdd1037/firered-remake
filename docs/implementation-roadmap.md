# 当前实施顺序

更新：2026-10-21。本页维护开发优先级与完成条件。完整目标见[范围合同](scope.md)，已实现/待验证/后置内容见[当前范围](first-clear-remaining-scope.md)，结构问题见[质量与维护](project-quality-review.md)。旧阶段清单不能作为重新开发已接通内容的依据。

## 当前维护重点

先修复[已记录的构建阻塞](validation.md#最近一次检查)，核对缺失源码与现有调用。恢复构建后，再按实际问题整理运行时、工具和测试；局部变更执行相关检查，跨模块变更扩大回归。源码、素材、存档和构建产物分别管理，版本控制、资源交付和备份按具体任务管理。

旧存档兼容不再约束必要的结构调整，不为此保留迁移层；仍须拒绝不支持的格式、保留原文件，并保证当前格式的正常存读、完整性和备份安全。普通训练家登记、实际出场位置和共享目录应保持一致；不能把数据搬到配置、删除覆盖或压缩排版当作结构改进。

文档只保留可执行入口、契约、真实缺口和必要证据；不累计历史通过次数，不以测试数、文件数或代码量推算游戏完成率。验证记录须标明所属改动和范围，不将既有导出视为当前源码成品。

## 后续工作优先级

1. 以当前范围与实际源入口核对非汉化单机尚未关闭的表现和交互，区分未实现、已实现未验证与明确后置；先处理影响正常游玩的明确问题。专属招式身份已接入不代表所有控制器时序和原生视听已验收。
2. 按实际问题处理共享机制与性能：模态输入/生命周期、资源读取/初始化、仍有消费者的适配器及未闭合资源再生。优先测量再修改，不为减少文件数重建通用平台。
3. 在具备对应环境时补真实音频、Windows 及剩余代表性原生检查。P0 真实音频未关闭，但不因此停止已授权的完整单机开发；Dummy 结果不能替代此验收项。
4. 非汉化单机内容与必要表现完成后，按范围合同再次做完整审计。汉化、未批准规则变化及通信进化替代服务的具体地点/费用/入口，不在工程重构中自行决定。

审计发现缺口时，先确认当前组合中的真实调用和原作语义，不按旧阶段名称重复开发。普通内容经共享目录/机制接入，不加地区白名单、重复数值表或跨地区豁免；狩猎、教程和特殊剧情差异仍明确保留。

## 每批完成条件

- 执行受影响的规则、应用、内容、导入或表现检查；跨边界变更扩大回归，音频测试仍显式运行。不要为局部修改重放整条历史路线。
- 原生画面、独立包和真实音频分别验收，保留失败与未覆盖项，不把 ready 或托管测试成功写成完整交付。
- 更新对应契约/验证文档。独立包只报告实际完成的导出与运行检查；版本控制和交付操作按具体任务执行。
