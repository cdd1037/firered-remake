# 项目质量与后续维护

更新：2026-10-21。本页只维护当前结构问题、处理边界与验收要求。模块和业务契约统一见[架构](architecture.md)，功能缺口见[当前范围](first-clear-remaining-scope.md)，执行次序见[实施顺序](implementation-roadmap.md)。已完成批次的过程留在 Git，不再累计里程碑或性能数字。

## 维护基线

当前已采用单一游戏组合、普通单/双打四位置内核、共享物种/招式/道具/机器/训练家定义及统一世界编译入口。普通菜单、遇敌、库存和持物查询复用实际目录与业务事务，不应恢复历史地区开关、前驱资源链或重复数值表。

资源读取、像素上传、训练家生成、原作文本提取及导入公共层各保留共同实现；确实不同的布局、调色、狩猎、教程和特殊剧情仍明确表达。合并依据是语义相同，不是文件名相似或“去 source”字样。

构建、回归与原生覆盖统一见[验证与限制](validation.md)。存档省略项、准入结构与图集契约分别维护在[存档](save-storage.md)、[宝可梦准入](current-content-composition.md#宝可梦准入)、[训练家卡图集](features/trainer-card-and-photo-printer.md#resources-and-checks)，不在本页重复测量日志。

## 构建与验证状态

2026-10-21 已修复开发入口的还原方式，补齐共享训练家目录和地区加载器，并恢复仍有实际调用的文本、名称与菜单组件。标准解决方案构建和 `python dev build` 均通过，未恢复已被共享路径替代的地区工厂。受控存档仍缺少独立验证的 schema 3 输入；准确命令、失败记录和回归边界见[验证记录](validation.md#最近一次检查)。构建通过不等于语言包、原生窗口、完整路线或音频验收。

## 仍需处理的结构边界

### 战斗与剧情

- 实验室首战仍有独立教程执行器。可逐步接公共规则，但须保留教程输入、AI 与演出差异。
- 训练家 AI 仍有基于源脚本偏移的修正。修改相关程序时宜转为明确指令/标签转换，保留源随机抽样顺序，不顺便改变难度；AI 的静态查询不应直接调用完整战斗行动执行器。
- 少数特殊剧情按源路径/标签分派。先区分实际业务身份与历史包装，再收敛普通逻辑；具名特殊处理器不应被万能框架取代。
- 普通单打、双打及 Teachy TV 已直接消费 canonical 事件，旧表现 DTO 与往返适配已移除。换人子页、教程输入和奖励逐级显示仍有真实差异，后续不得把它们简化为无条件推进同一游标。
- 普通单打家族已使用共享训练师目录与实际出场登记，删除了独立地区工厂和重复选择器；混合双打、联盟、再战与教程仍有明确不同的入口。后续收敛须保留真实脚本调用、演员/地图、后续对白和特殊战斗差异，不把训练师身份误当唯一出场位置。Route4 Crissy 的既有遗漏已通过共享导入选择补齐；当前编译的普通 single/no-intro 调用有完整身份闭合测试，但不据此推断其他特殊模式也已全部验收。

### 模态流程与资源

- `CampaignSession`、`CampaignView` 仍有较多 partial，模态功能跨输入、命令、preflight、保存忙态与演出。按真实修改需要集中职责，不引入 ECS、DI 容器或通用插件平台。
- 部分专用表现/图标转换入口尚未统一。优先合并相同解析、注册及生命周期，不抹平特殊布局、调色、地图机关或源时序。
- generated 的全量冷重建尚不完整。world 和已列明功能目标的成功不能代表所有 UI、剧情和音频 pack 都可一条命令重建；必要私有资源必须保留。
- 全量资源验证仍缺部分独立参考向量，也不能用定向通过代替全量复测。已修正 indexed/RGB 重复声明、相关旧测试假设、可变调色板缓存，以及核实来源后的参考 pin 和 Quest 名称／地图准入边界；仍不得放宽来源校验或覆盖 golden 消除其他失败。
- 全地区表现初始化仍有同步工作。先实测重复解码、临时分配及进入地图成本，再优化；不能用大缓存掩盖生命周期问题。

## 每批改动的验收要求

1. 先确认实际调用、数据权威和目标行为，再删除或合并；新增内容经过共享机制，不靠地名白名单、重复表或验证豁免接入。
2. 局部变更运行受影响项目及必要原生冒烟；跨边界或共享测试配置变更扩大回归。具体命令见[测试说明](../tests/README.md)。共享只读正例，改文件的负例用隔离副本，保留独立数值向量、确定性和失败路径。
3. 记录准确命令、输入、引擎/运行时、通过/失败及未覆盖范围。定向测试不称全套通过；静态源码检查不代替产品行为，纯 C# 表现检查不代替 Godot 画面。
4. 性能比较须同口径，写清累计分配、耗时或资源数量的实际含义。它们不等于峰值内存、GPU 内存、游戏帧率、磁盘延迟或听感。
5. 不为局部重构反复重放历史全路线，不重写 golden 迎合实现，不把代码搬入另一目录/配方当作真正减量。

不新增历史证明注册中心或全工程 hash 锁。内部 API/存档结构调整须先明确业务职责与版本边界，保留真实状态和必要检查点，不以破坏兼容为目标。

存档完整性、有效主档/备份、版本准入和明确 RNG 是产品契约，不是可删除的取证负担。旧档缺失的真实终身孵蛋次数不能推算；测试合成值不代表玩家历史。规则见[架构](architecture.md)和[存档说明](save-storage.md)。

## 验证与交付边界

- 工具链保持官方 Godot 4.7.2 .NET / `net10.0` / 实际 .NET 10 宿主。Linux 云环境使用 README 中的串行构建；Windows 开发工具可发现，但游戏运行与独立包未验收。
- P0 真实音频未关闭。headless/Dummy、离线合成或 ready 信号不证明扬声器输出、自然通关、帧率或优雅退出。
- 当前原生证据限于记录的代表场景和控制器，不等于完整 UI 状态或全游戏逐帧验收。已有 Linux 独立包的 Save/Continue 证据也不覆盖后续代码；[Linux 验收](history/linux-export-acceptance.md)与[Windows 状态](validation.md#windows)分开记录。
- 源码、私有素材、存档和成品分别管理。导出与运行结果必须对应具体版本；不为 CI 或预览公开原作素材，也不强制加入 Git。
- 工程仍是私有研究项目。未来公开前须解决作者许可证、第三方/原作片段与字体来源及再分发权限；来源固定不代表可公开分发。
