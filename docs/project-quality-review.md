# 项目质量与后续维护

更新：2026-10-16。本页只保留当前结构、未解决问题和维护约束。具体玩法范围以
[first-clear-remaining-scope.md](first-clear-remaining-scope.md) 为准；历史实施过程由 Git 保存。

## 当前工程边界

- 根目录为普通工程：src、tools、scripts、tests、docs、content、checkpoints。
  源码提交 Git；私有素材和代表存档由普通工程包携带，不强制加入源码仓库。
- Domain 为确定性规则；Application 负责命令、状态转换与事务；Content 负责已生成
  数据的解析/引用校验；Godot 负责表现和输入；Audio 为游戏与工具共用的合成器。
- 运行只读取 generated，不解析 pret/C/ASM，也不依赖导入脚本或原始来源清单。
  原始来源、选择和转换属于离线工具。见[资源再生成](resource-reconstruction-guide.md)。
- 当前仅维护一个完整游戏组合。删除历史地区功能开关、190 参数构造搬运、地区物种/
  机器增量投影及重复 ownership/opponents 别名。实际资源由构造时加载，缺失或非法
  数据必须失败；徽章、剧情、图鉴解锁等玩家状态条件仍保留。

## 已收敛的共享实现

- 世界由统一 raw→world 编译器生成，运行组合只加载一次世界。真实地图、布局变体、
  事件、NPC 和图集均保留；不靠上一阶段包或固定历史数量证明有效。
- 招式能力由实际战斗内核的实现注册决定，学习和入场共用；删除历史地区 BattleScope
  放行链。定义仍校验合法范围与目录归属。普通单/双打使用同一四位置内核。
- 训练家共用生成与自定义招式投影，保留原 RNG 顺序、PID/OT、队伍格式、持物、奖励
  与同脚本多次调用的真实身份。
- 后期五组野怪重复数值表改用 canonical 物种/学习表/能力/持物数据。普通陆地和 Surf
  战斗都绑定实际已验证表与候选，不允许仅因物种在目录中就绕过遇敌来源。
- 水域组合保留真实五槽、权重、等级及引用检查；重叠地图定义相同则复用，冲突则拒绝。
  不再串联前驱目录与历史数量。Safari、游走、Unown、事件神兽仍有不同规则。
- Content 的普通宝可梦表现共用类型化读取器，Godot 表现包与纹理注册共用实现。
  尺寸检查与实际 PNG 上传共用一次解码；复用已有场景纹理所有权，不加长期 CPU 像素缓存。
- 通用路径、严格 JSON、导入源解析、像素转换与测试进程调用使用共享实现。已经无消费者
  的报告、阶段脚本及输出一起退休，不把无用运行字段换成忽略的占位字段。

## 日常行为与状态

- 普通命令不做全状态 Hash；详细取证与逐帧日志按需开启。
- 野战与取得来源按实际业务引用归约；当前队伍、盒子、培育屋和 PC 手持个体是所有权。
  放生/交易不永久保存完整离场实体。一次性履约、图鉴、统计与名人堂快照是独立游戏事实。
- revision、明确 RNG、不可变状态与原子提交保留。存档完整性校验、主档/备份和结构化
  错误仍有作用；不能把业务保障当作无用防御性代码删除。
- 旧代表档缺失真实终身孵蛋次数，不能猜测恢复。普通 Continue 不静默迁移；已知值才可
  显式转换。测试中的固定合成值不是玩家历史。见 [Sticker Man](sticker-man.md)。
- 字体和声音合成核心本轮不改。音频测试仍单独按需执行，不进入默认全量测试。

## 仍值得继续处理

### 战斗与剧情边界

- 实验室首战仍是单独的教程执行器。已有受限能力与源向量验证；未来可逐步接公共规则，
  但不能直接删除教程输入、AI 与演出差异。
- 训练家 AI 仍有基于原脚本偏移的修正；若修改原 AI，应改为明确指令/标签转换。
  不顺便重新设计玩法或 AI 难度。
- 少数专门剧情仍按源路径/标签分派。共享普通菜单已使用实际菜单目录；真正特殊的
  事件应保留具名处理器，不能为了去 source 字样盲删业务身份。
- 当前单/双打仍需向旧表现模型投影。迁移消费者后再精简适配器；不要把有活调用的
  适配器当死代码删除。

### 模块与资源

- CampaignSession 和 CampaignView 仍有较多 partial，模态玩法需协调输入、命令、
  preflight、保存忙态与演出。可按实际职责逐步集中，但不引入 ECS、DI 容器或通用平台。
- 尚有专用表现/图标转换入口未完全统一。优先合并真正相同的解析和注册，不把特殊
  布局、调色差异、地图机关硬塞进一个万能脚本。
- generated 仍不是可随时删除的缓存。已证明的 world/功能编译闭包不能代表所有专用
  UI、剧情与音频 pack 已支持一条命令冷重建；私有工程资源仍需保留。
- 全地区表现初始化仍有同步工作。优先实测重复解码、临时分配与进入地图成本；
  不用“大缓存”掩盖问题，也不把累计分配或场景所有权计数称作峰值 GPU 内存。

### 验证与交付

- 标准串行构建和按项目测试是默认入口。共享只读夹具；修改文件的负例仍用隔离副本。
  保留独立数值向量、跨进程确定性、快速招式矩阵与有价值的失败路径。
- 纯 C# 表现测试不能证明实际 Godot 画面正确。headless/Dummy 达到 ready 不代表
  扬声器听感、自然通关、帧率、优雅退出或导出成品已经验收。
- 已有真实 Linux 导出/普通启动路径；Windows、完整 UI 操作与实际音频仍需相应环境
  单独验证。不要为自动化 CI 把私有游戏素材公开或强塞进 Git。
- 公开前仍需明确作者许可证及第三方/原作片段和字体来源。目前为私有研究工程。

## 后续改动标准

先找实际调用与数据权威，再删除或合并。一次有边界的变更配对应测试和必要引擎冒烟，
不得为了行数牺牲业务差异，也不得为了验证反复重放整条历史路线。完成后的统计应包含
新增共享代码与测试，不靠搬目录、压行或复制到配方文件制造减量。
