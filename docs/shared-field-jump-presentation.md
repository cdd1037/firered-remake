# Shared field jump presentation

Live field movement and Quest Log playback use the same pure source movement sample. Recorded source actions, start times, durations and accepted destination coordinates remain authoritative; no save field or gameplay command was added.

The source `event_object_movement.c` regular far/high jump moves one pixel per callback for 32 callbacks. Special/high jumps move on alternating callbacks for 32 callbacks. In-place high and reversing in-place normal jumps take 16 callbacks. The shared sample uses the original high/normal Y tables, keeping sprite Y offset separate from the tile/world/camera anchor. Its elapsed value counts completed callbacks: zero is the pre-movement pose, one includes the initializer's immediate first update, and the final callback clears Y2. This removes the prior live ledge/Surf table duplication and their inconsistent elapsed offsets. All four directional far jumps share the same path, rather than recognizing only downward scripted ledges.

The timeline already retained each SourceAction; it now exposes the shared Y offset alongside position fraction. Recap special jumps also use the discrete alternate-pixel schedule instead of linear interpolation. Surf rider offset is applied to the rider, leaving the blob/world anchor unchanged. Existing recorded durations and gameplay outcomes are unchanged.

This closes displacement/arc presentation only. Direction-reversal animation selection, shadow/landing field effects and the broader special-pose catalog are separate. New supported transitions now carry producer-owned cause/phase evidence and share the live/recap transition controller; see [ordinary transitions](plain-field-transition-presentation.md). Historical destination-only records still do not identify warp versus connected-edge/forced transitions, so no fade is inferred from those map changes.
