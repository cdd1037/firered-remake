# Focused shared caller verification

Run once through the product's pinned official SDK/runtime:

```sh
bash tests/Game.FourCallers.Tests/run.sh PRODUCT_ROOT PINNED_POKEFIRERED_ROOT FRESH_OUTPUT
```

The candidate source/project root is derived from this script. Product content and
toolchains are read from PRODUCT_ROOT. Builds serialize on
`/tmp/firered-remake-build.lock`, use `-m:1 -nr:false`, and never run another suite.
The source probe reads Git objects and source files only; it never runs a script
from the reference checkout. `cc` compiles the generated isolated C oracle in
optimized and UBSan configurations.

`baseline-a51e8a6.json` and its SHA-256 were captured before production edits from
16 complete canonical singles caller results. They are immutable expectations,
not regenerated by run.sh. The temporary `--capture` command existed only for the
pre-edit capture; the retained fixture records the complete outputs.

Required authored dependencies are this project, Program.cs, packages.lock.json,
source_probe.py, run.sh, the frozen JSON/SHA, and the product Domain/Content
projects plus its authenticated content. The probe generates source-oracle.c,
source-vectors.csv and source-proof.json in the fresh output directory; no external
C fixture path or untracked reference header is needed.

The source oracle covers 512 first-draw Metronome values, 256 four-battler Mirror
histories, and 256 Sleep Talk position/limitation cases. The C# suite verifies every
vector, all 336 legal Metronome first results, actual four-action caller execution,
and preserved canonical singles results. Negative recipe tests discover a current
unmigrated legal result dynamically; once all results migrate, the test verifies
the complete pool without treating any unrelated move as permanently unsupported.

Initial development retained one failed compile (incorrect test receipt property
names) and fixture failures (unmigrated Splash placeholders, duplicate learned
moves, wrong test targets, missing reward context). These were corrected in the
fixtures; no frozen expectation was changed. All iteration logs remain in the
isolated work directory's evidence tree.
