# Shared Pursuit and Beat Up

This bounded source capability migrates both commands to the slot-typed recipe context.
Canonical singles use the same commands through the singles storage bridge; old campaign
profiles retain their original branches. Real four-position turns retain the existing
action, target, end-turn, entry, reward and learning owners.

Pursuit reads the pending voluntary switch and original selected target. It checks the
opponent right position before left regardless of speed, consumes the original chosen
Pursuit action, skips normal cancellation/accuracy/secondary commands and doubles damage.
Its restricted move-end slice excludes normal history, berries and Shell Bell/King's Rock.
A KO retains the exact outgoing identity and reserved incoming member while the existing
reward/learning owner runs. The same switch action then resumes. A second Pursuit whose
outgoing target already fainted remains queued and attacks the actual entrant normally.
Forced switches and Baton Pass do not invoke this interception path. Called Pursuit uses
the normal move recipe, because the chosen action is the caller.

Beat Up walks actual party indices and excludes status, fainted and egg members. Each hit
uses the contributor's base Attack and level and the target battle species' base Defense,
with Helping Hand, critical and random modifiers in source order. It has no typecalc/STAB
and no contact flag. Each hit visits Substitute, survival adjustment, Color Change, berries,
held items and history exactly once; target KO ends the contribution loop. One caller/learned
PP slot owns the whole move. Both moves preserve actual selected ally/opponent positions.

bash tests/Game.SharedPursuitBeatUp.Tests/run.sh CONTENT_ROOT PINNED_PRET_ROOT NEW_OUTPUT

local-only NuGet configuration and shared build lock, with bin/obj isolated in this snapshot.

captured before any product edit against `bfc976e21084ba2ad0b7a2f9da0652ccdab6c7e3`.
