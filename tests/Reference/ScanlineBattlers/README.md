# Four source scanline consumers

Run explicitly from the repository root:

`python tests/Reference/ScanlineBattlers/generate.py --root . --output tests/Game.Presentation.Tests/Fixtures/scanline-battler-source-vectors.json`

The output must not exist. It is local ignored expected data, never regenerated by ordinary tests. `--full` uses the same comparator with every attacker/target layout.

The generator extracts original pinned C callbacks for Dig down/up, Sketch drawing/pencil, Dragon Dance distortion/orbs, Acid Armor and the shared tagged palette pulse. It compiles only this bounded harness at O0 and O2 and requires byte-identical observations. No third-party build script runs.

The representative definition covers each side and BG rank, both Dig modes, every authored orb starting angle, both mound halves, zero-wait destructor handoff, single-frame arc, signed16 destination wrap, short source pictures, nonzero picture offsets/elevation, byte-coordinate wrap, retained nonzero banks and initial source-buffer 1. All 83 complete lives and 6,993 callback rows are compared. The two 960-word banks are stored as lossless changes; every unchanged word remains part of the comparison. Task data, remaining argument registers, BG/alpha writes, visibility, positions, palette entries and pencil audio are observed each row. Static dummy sprite tables intentionally leave native tile offsets intact.

The harness models only the engine's inter-row stop/flip boundary. It does not claim GPU queue or row-zero timing: the shared scanline engine's source vectors own that separate contract. Native function bodies, tables and pin hashes are checked; coordinate fixtures are explicit call inputs based on the source battle layout and picture dimensions. Expected JSON stays ignored. Managed full-root tests use canonical scripts, materials, scene ownership, source visibility and the shared composer.
